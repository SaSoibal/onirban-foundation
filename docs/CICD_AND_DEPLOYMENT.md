## 2. GitHub Secrets

Configure these in **Settings → Secrets and variables → Actions**:

### Frontend Secrets
| Secret | Value | Required |
|--------|-------|----------|
| `GITHUB_TOKEN` | Auto-generated by GitHub | Yes (default) |

### Backend Secrets
| Secret | Value | Required |
|--------|-------|----------|
| `RAILWAY_TOKEN` | Railway API token | Yes |
| `DB_HOST` | `127.0.0.1` (for CI only) | CI only |
| `DB_PORT` | `3306` | CI only |
| `DB_DATABASE` | `onirban_test` | CI only |
| `DB_USERNAME` | `root` | CI only |
| `DB_PASSWORD` | `root` | CI only |

**Railway Token Creation:**
1. Go to https://railway.app/account/tokens
2. Create new token with name `github-actions`
3. Copy token and paste in GitHub Secrets as `RAILWAY_TOKEN`

## 3. Frontend Workflow

**File:** `.github/workflows/frontend.yml`

```yaml
name: Frontend CI/CD

on:
  push:
    branches: [ main ]
    paths:
      - 'frontend/**'
  pull_request:
    branches: [ main ]
    paths:
      - 'frontend/**'

jobs:
  lint-and-test:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json
      - run: npm ci
      - run: npm run lint
      - run: npm run test -- --watch=false --browsers=ChromeHeadless
      - run: npm run build

  deploy:
    needs: lint-and-test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: frontend/dist
          publish_branch: gh-pages
          force_orphan: true
          user_name: 'github-actions'
          user_email: 'github-actions@github.com'
```

**Frontend Package.json Scripts:**
```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "lint": "eslint src --ext .jsx,.js",
    "test": "jest",
    "preview": "vite preview"
  }
}
```

## 4. Backend Workflow

**File:** `.github/workflows/backend.yml`

```yaml
name: Backend CI/CD

on:
  push:
    branches: [ main ]
    paths:
      - 'backend/**'
  pull_request:
    branches: [ main ]
    paths:
      - 'backend/**'

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: root
          MYSQL_DATABASE: onirban_test
        ports:
          - 3306:3306
        options: >-
          --health-cmd="mysqladmin ping"
          --health-interval=10s
          --health-timeout=5s
          --health-retries=3
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
          extensions: mbstring, bcmath, mysql, pdo_mysql, tokenizer, xml, ctype, json, curl
          coverage: xdebug
      - uses: actions/cache@v4
        with:
          path: backend/vendor
          key: ${{ runner.os }}-php-${{ hashFiles('backend/composer.lock') }}
          restore-keys: ${{ runner.os }}-php-
      - name: Install Composer dependencies
        run: |
          cd backend
          composer install --no-interaction --prefer-dist
      - name: Prepare environment
        run: |
          cd backend
          cp .env.example .env
          php artisan key:generate --force
      - name: Run migrations
        run: |
          cd backend
          php artisan migrate --force --env=testing
        env:
          DB_CONNECTION: mysql
          DB_HOST: 127.0.0.1
          DB_PORT: 3306
          DB_DATABASE: onirban_test
          DB_USERNAME: root
          DB_PASSWORD: root
      - name: Run tests
        run: |
          cd backend
          php artisan test --coverage
        env:
          DB_CONNECTION: mysql
          DB_HOST: 127.0.0.1
          DB_PORT: 3306
          DB_DATABASE: onirban_test
          DB_USERNAME: root
          DB_PASSWORD: root

  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
          extensions: mbstring
      - uses: actions/cache@v4
        with:
          path: backend/vendor
          key: ${{ runner.os }}-php-${{ hashFiles('backend/composer.lock') }}
      - run: |
          cd backend
          composer install --no-interaction --prefer-dist
      - run: |
          cd backend
          ./vendor/bin/pint --test

  deploy:
    needs: [test, lint]
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
      - uses: actions/cache@v4
        with:
          path: backend/vendor
          key: ${{ runner.os }}-php-${{ hashFiles('backend/composer.lock') }}
      - run: |
          cd backend
          composer install --no-dev --no-interaction --prefer-dist
      - uses: railwayapp/railway-action@v1
        with:
          railway-token: ${{ secrets.RAILWAY_TOKEN }}
          service: onirban-api
        env:
          RAILWAY_PROJECT_ID: ${{ secrets.RAILWAY_PROJECT_ID }}
          RAILWAY_SERVICE_ID: ${{ secrets.RAILWAY_SERVICE_ID }}
```

**Note:** If `railwayapp/railway-action` requires `RAILWAY_PROJECT_ID` and `RAILWAY_SERVICE_ID`, create them in Railway dashboard or infer from URL.

## 5. Railway Deployment Setup

### 5.1 Create Railway Project
1. Go to https://railway.app/new
2. Create new project `onirban-foundationapi`
3. Add MySQL plugin (Railway will provision a MySQL instance)
4. Note the MySQL connection details from Railway dashboard

### 5.2 Connect GitHub Repo
1. In Railway project, go to **Settings → GitHub**
2. Connect repository `SaSoibal/onirban-foundation`
3. Select `backend` as service root directory

### 5.3 Environment Variables (Railway)
Set these in Railway dashboard under **Variables**:

| Variable | Value | Notes |
|----------|-------|-------|
| `APP_NAME` | Onirban Foundation | |
| `APP_ENV` | production | |
| `APP_KEY` | (generated by Railway build) | |
| `APP_DEBUG` | false | |
| `APP_URL` | https://api.onirban-foundation.railway.app | |
| `LOG_CHANNEL` | stack | |
| `DB_CONNECTION` | mysql | |
| `DB_HOST` | (from Railway MySQL plugin) | |
| `DB_PORT` | (from Railway MySQL plugin) | |
| `DB_DATABASE` | (from Railway MySQL plugin) | |
| `DB_USERNAME` | (from Railway MySQL plugin) | |
| `DB_PASSWORD` | (from Railway MySQL plugin) | |
| `BROADCAST_DRIVER` | log | |
| `CACHE_DRIVER` | file | |
| `FILESYSTEM_DISK` | public | |
| `QUEUE_CONNECTION` | database | |
| `SESSION_DRIVER` | cookie | |
| `SESSION_LIFETIME` | 120 | |
| `SANCTUM_STATEFUL_DOMAINS` | sasoibal.github.io | |
| `SESSION_DOMAIN` | .sasoibal.github.io | |

### 5.4 Build Command
Railway auto-detects PHP. Set **Build Command**:
```bash
cd backend && composer install --no-dev --no-interaction --prefer-dist && php artisan migrate --force
```

### 5.5 Deploy Command
```bash
cd backend && php artisan config:cache && php artisan route:cache && php artisan view:cache
```

### 5.6 Domain Setup
1. In Railway, go to **Settings → Domains**
2. Add custom domain `api.onirban-foundation.railway.app` (Railway provides this by default) or connect custom domain
3. Ensure HTTPS is enforced

## 6. Frontend GitHub Pages Setup

### 6.1 Repository Settings
1. Go to repo **Settings → Pages**
2. Source: **Deploy from a branch**
3. Branch: `gh-pages` / `dist` (root)
4. Save

### 6.2 Custom Domain (Optional)
If using custom domain later, add CNAME file to `frontend/public/CNAME` with value `onirban-foundation.org`

### 6.3 404.html for BrowserRouter
If using BrowserRouter (recommended), add `frontend/public/404.html`:
```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8">
    <title>Onirban Foundation</title>
    <script>
      (function() {
        var path = window.location.pathname;
        var base = '/onirban-foundation';
        var relative = path.replace(base, '') || '/';
        window.location.replace(base + '/#' + relative);
      })();
    </script>
  </head>
</html>
```
This ensures all unmatched GitHub Pages routes redirect to the React app.

## 7. MySQL Database Setup (Railway)

### 7.1 Provisioning
Railway MySQL plugin automatically provisions a database. Access credentials from **Variables** tab.

### 7.2 External Access (Optional)
For local development, enable **Public Network** in Railway MySQL settings. Use the provided host, port, username, password.

### 7.3 Backup
Railway provides automatic backups. For manual backup:
```bash
mysqldump -h <host> -u <user> -p <database> > backup.sql
```

## 8. Step-by-Step Deployment Checklist

### Phase 1: Initial Setup
- [ ] Create GitHub repo: `SaSoibal/onirban-foundation`
- [ ] Clone repo locally
- [ ] Create folder structure: `backend/`, `frontend/`, `docs/`, `.github/workflows/`
- [ ] Push initial structure to GitHub

### Phase 2: Backend Deployment
- [ ] Create Railway project `onirban-foundationapi`
- [ ] Add MySQL plugin to Railway
- [ ] Connect Railway to GitHub repo
- [ ] Set Railway environment variables
- [ ] Push backend code to trigger first deploy
- [ ] Verify API health at `https://api.onirban-foundation.railway.app/api/health`
- [ ] Run database migrations via Railway CLI or dashboard

### Phase 3: Frontend Deployment
- [ ] Set frontend environment variable: `VITE_API_BASE_URL=https://api.onirban-foundation.railway.app/api`
- [ ] Push frontend code to trigger GitHub Actions
- [ ] Verify GitHub Actions run and deploy to `gh-pages` branch
- [ ] Verify site at `https://sasoibal.github.io/onirban-foundation/`
- [ ] Test CORS by making API call from frontend

### Phase 4: CI/CD Verification
- [ ] Open PR with backend change → verify backend workflow runs
- [ ] Open PR with frontend change → verify frontend workflow runs
- [ ] Merge to main → verify deploy triggers
- [ ] Check Railway logs for successful backend deploy
- [ ] Check `gh-pages` branch for updated frontend

### Phase 5: Hardening
- [ ] Enable Railway automatic deploys from main branch
- [ ] Add branch protection rules on GitHub (require PR reviews, passing CI)
- [ ] Configure Railway alerts for downtime
- [ ] Add monitoring (Sentry for frontend, Laravel Telescope for backend - dev only)
- [ ] Set up backup retention policy on Railway MySQL

## 10. Rollback Strategy

### Frontend Rollback
1. Go to GitHub repo → Settings → Pages
2. Revert `gh-pages` branch to previous commit
3. Or use GitHub UI to redeploy previous build

### Backend Rollback
1. In Railway dashboard → Deployments
2. Find previous successful deployment
3. Click **Redeploy** on previous version
4. Or use Railway CLI: `railway rollback`
